# 簡繁轉換規則

本文件定義 Claude 在處理本專案檔案時應遵守的文字轉換規則。

## 適用範圍

- 所有檔案內容（`.md`、`.txt`、`.html`、`.js`、`.ts`、`.css`、`.json`、程式碼註解、字串等）
- 目錄名稱
- 檔案名稱

## 規則一：簡體中文 → 繁體中文

凡偵測到簡體中文字元，一律轉換為對應的繁體中文（台灣正體用字為主）。

### 應用對象

| 對象 | 處理方式 |
| --- | --- |
| 檔案內容 | 直接以 Edit/Write 修改 |
| 檔案名稱 | 使用 `git mv`（若在 git 控管下）或 `mv` 重新命名 |
| 目錄名稱 | 使用 `git mv` 或 `mv` 重新命名 |

### 轉換方式：字元層級（使用台灣字形變體）

**只做字元對字元的簡→繁轉換，使用台灣習慣的字形變體，但不替換詞彙。**

- 使用 **OpenCC `s2tw`** 設定檔：套用台灣字形變體（例：`爲` → `為`、`衆` → `眾`、`什麽` → `什麼`）
- **不使用** `s2twp`，因為 `s2twp` 會做詞彙替換（如 `軟件` → `軟體`）
- 保留原作者的用詞習慣；`軟件`、`網絡`、`程序`、`鼠標` 等**維持原樣**

#### 後置字元替換表（補 OpenCC 未處理的台灣變體）

OpenCC `s2tw` 沒有覆蓋到的字元變體，以下表做**一對一字元替換**：

| 原字 | 替換為 | 常見詞例／理由 |
| --- | --- | --- |
| 賬 | 帳 | 賬號→帳號、賬戶→帳戶、賬單→帳單 |
| 檯 | 台 | 控制檯→控制台、櫃檯→櫃台 |
| 瞭 | 了 | 還原 OpenCC 的短語級替換（例：`為了解決` 被誤判為含 `了解`→`瞭解`）。簡體原文不使用 `瞭`，一律還原為 `了` 以符「一字對一字」 |

> 未列入此表的字元（例如 `軟`、`件`、`網`、`絡` 等），即使台灣有其他寫法，**一律保留 OpenCC 輸出不再替換**。

#### 詞彙不替換的原則示例

| 原文（簡體） | 轉換後（繁體） | 說明 |
| --- | --- | --- |
| 软件 | 軟件 | 不改成「軟體」 |
| 网络 | 網絡 | 不改成「網路」 |
| 服务器 | 服務器 | 不改成「伺服器」 |
| 数据 | 數據 | 不改成「資料」 |
| 程序 | 程序 | 不改成「程式」 |
| 变量 | 變量 | 不改成「變數」 |
| 对象 | 對象 | 不改成「物件」 |
| 文件夹 | 文件夾 | 不改成「資料夾」 |
| 默认 | 默認 | 不改成「預設」 |
| 设置 | 設置 | 不改成「設定」 |
| 缓存 | 緩存 | 不改成「快取」 |
| 打印 | 打印 | 不改成「列印」 |
| 鼠标 | 鼠標 | 不改成「滑鼠」 |

> 原則：**一字對一字**（含台灣變體）。不做地區用詞替換、不做語意改寫、不調整語序。

### 不可轉換的例外

以下內容即使含簡體字元也**不得**轉換，以免破壞功能：

1. **URL / 連結路徑**（含 http(s)://、相對路徑中的簡體字）
2. **套件名稱、npm 套件 ID、module 名稱**
3. **程式識別字**：變數、函式、類別、常數名稱等（即使以拼音或中文命名）
4. **字串若為 API 參數、資料庫欄位、協定關鍵字**
5. **第三方原始碼、node_modules、.git 目錄內檔案**
6. **lock 檔**（`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml` 等）
7. **程式碼區塊內的識別字**（Markdown 中 ``` ``` 內的程式語法關鍵字）

> 註解與 UI 字串仍需轉換。

## 規則二之前：CJK 標點前的多餘空白清除

當 **非空白字元** 與 **全形標點** 之間插入了空白（半形空格、全形空格、Tab），一律刪除該空白，使標點緊貼前字。

### 適用標點

`、`、`。`、`！`、`，`、`：`、`；`、`？`、`）`、`」`、`』`、`】`、`》`

### 範例

| 轉換前 | 轉換後 |
| --- | --- |
| 需要包管理器 ？ | 需要包管理器？ |
| 註冊地址 ，以便發佈 | 註冊地址，以便發佈 |
| 什麼是 workspace ？ | 什麼是 workspace？ |

### 適用範圍

- **僅套用在 `.md` 檔案的自然語言段落**
- **程式碼區塊（``` … ```）與行內程式碼（`…`）內不套用**
- 其他副檔名（`.vue` / `.ts` / `.js` / …）不套用，避免誤動格式化字串

### 實作（正規表示式）

```
pattern: (?<=\S)[ \t\u3000]+(?=[、。！，：；？）」』】》])
replace: ""
```

> 只刪除非換行空白。行首縮排（換行後的空白）不受影響。

## 規則二：成對引號 `""` → 「」

凡成對出現的半形或全形雙引號 `"…"` / `“…”`，用於中文語境之引用、書名、強調或對話時，一律轉為「…」。

### 轉換範例

| 轉換前 | 轉換後 |
| --- | --- |
| 他說："你好。" | 他說：「你好。」 |
| 點選"確認"按鈕 | 點選「確認」按鈕 |
| “資料結構” | 「資料結構」 |

### 巢狀引號

外層使用「」，內層使用『』：

| 轉換前 | 轉換後 |
| --- | --- |
| "他說"你好"。" | 「他說『你好』。」 |

### 不可轉換的例外

以下情境中的 `"` **不得**轉換：

1. **程式碼字串**：`const msg = "hello"` → 保留
2. **JSON / YAML / TOML 鍵值**：`"name": "..."` → 保留
3. **HTML / XML 屬性**：`class="foo"` → 保留
4. **命令列參數**：`--flag="value"` → 保留
5. **正規表達式、路徑字面值**
6. **Markdown 程式碼區塊**（``` … ``` 或 `…` 內）
7. **英文語境**的直接引用（例如 `"Hello World"` 作為英文短語）

> 判斷原則：若引號位於**自然語言的中文段落**中，才轉換；若位於**程式語法**中，一律保留。

## 執行流程（Claude 處理順序）

當使用者要求對檔案或目錄執行轉換時：

1. **掃描**：找出所有含簡體字元或成對 `""` 的檔案 / 目錄 / 檔名
2. **分類**：依上述例外規則判斷哪些需轉換、哪些保留
3. **預覽**：列出將要變更的清單（路徑、重新命名對照、引號替換統計）給使用者確認
4. **執行**：取得同意後，依序套用
   - 先改檔案內容
   - 再重新命名檔案
   - 最後重新命名目錄（由深層往淺層）
5. **驗證**：轉換完成後，再次掃描確認無漏網之魚
6. **報告**：**每次執行完成後必須給使用者一份轉換進度報告**，內容至少包含：
   - 已處理檔案數 / 目錄數 / 重新命名數
   - 字元轉換統計（簡→繁字數、引號替換次數）
   - 遇到的例外或略過項目
   - 剩餘未處理項目（若為分階段執行）

## 計畫與報告規範

- **擬定轉換計畫時不要附帶 git commit 建議**（不列分批 commit 節奏、不建議 commit 訊息）
- 分階段執行時，每一階段結束都要主動回報進度（同第 6 點）
- 計畫只聚焦於「要改什麼、怎麼改、順序」，版本控管由使用者自行決定

## 風險與安全

- 涉及檔名或目錄重新命名時，若處於 git 控管下，優先使用 `git mv` 以保留歷史
- 每次執行僅處理使用者明確指定的範圍，不主動擴大
